# Chatz API reference (English)

> **Full Chinese reference**: [API.md](API.md) — it carries every field table, edge case and
> historical note. This English file is a **condensed but complete** reference: every endpoint,
> its request/response shape, status codes and limits. Identifiers (paths, JSON keys, header
> names) are identical in both files, so code samples transfer as-is.

## Auth

### Three credential types

| Credential | Format | Scope |
|---|---|---|
| Master key | `cz.` + 30 base62 chars | Super-admin identity. Also what an admin's password login returns |
| Device token | same format | Issued per device at sign-up / setup / "add device"; **reused across logins** |
| App token | 10 base62 chars | **Only** for `POST /hook/<app-token>`; no `Bearer` prefix |

Send a user credential in any of three ways:

```http
Authorization: Bearer <token>
X-Gotify-Key: <token>
GET /message?token=<token>
```

`X-Gotify-Key` exists purely for Gotify compatibility. The `cz.` prefix is a **readability
marker, not a security boundary** — authentication is always an exact whole-string match against
the `devices` table (the master key is compared against the configured value).

### Where the master key comes from

| Source | How | Notes |
|---|---|---|
| `AUTH_TOKEN` | plaintext env var | ⚠️ shows up in `docker inspect`, `docker compose config`, dashboards |
| `AUTH_TOKEN_FILE` | env var holding a **path** | ✅ preferred — only a path is exposed; works with docker/k8s secrets. File is trimmed on read |
| `meta.auth_token` in the DB | generated by the setup page | **default**. Nothing to configure |
| — | — | On a fresh install the key **does not exist yet**; `POST /setup` creates it |

Resolution order is `AUTH_TOKEN` → `AUTH_TOKEN_FILE` → database → *uninitialized*.
On every boot the effective value is written back into the database, so **removing the env var
later does not change the key** — the source simply flips from `[环境变量]` to `[数据库]` in the
startup log. Watch the 8-character fingerprint: if it changes, you fell back to an old value.

🔴 If `AUTH_TOKEN_FILE` is set but the file is missing or empty, the server **refuses to start**
rather than silently reusing an old key.

### Status code convention

| Code | Meaning |
|---|---|
| `400` | Bad request / invalid argument |
| `401` | **The Bearer credential itself is invalid or expired** — re-authenticate |
| `403` | Authenticated, but this specific step is refused (wrong password, insufficient role) |
| `404` | Not found — also returned when the row exists but belongs to another user |
| `413` / `507` | Attachment too large / total quota exceeded |

🔴 **Never return `401` for "wrong password" on an endpoint the user is already authenticated
to.** The web client treats every `401` as "session expired": it clears local storage and jumps
back to the login page. Use `403` instead (see `POST /device/:id/reveal`).

Errors have a uniform shape:

```json
{ "error": "密码不正确" }
```

### Rate limiting & size limits

- In-memory, per instance. Keyed per IP unless noted otherwise
- Attachments: 8 MB each, 500 MB total (`413` / `507`)
- Image type is decided by **magic-number sniffing**, never by client-supplied extension or
  `Content-Type`

> Every example below uses a placeholder such as `cz.xxxxxxxx...`. Never commit a real key.

## 1. Basics

- `GET /health` (public) — liveness probe, used by the container healthcheck
- `GET /config` (public) — runtime flags the UI needs (HTTPS port, whether the certs UI is on)
- `GET /version` (login) — running version; keep in sync with `package.json`

## 2. Users & devices

### First install

- `GET /setup/status` (public) — is this a fresh install?
- `POST /setup` (public, 20/h/IP) — claim the first admin account. **This is where the master
  key is generated** (unless one was pinned via env). The response includes it; it is never
  printed to the container log

### Sign-in & password

- `POST /auth/register` (public, 3/h/IP) — registration is **open to everyone**; "requires
  login" is not an access control
- `POST /auth/login` (public) — returns the device token for this user, reusing the existing one
- `POST /auth/forgot-password` (public, 10/h/IP) — there is no SMTP: the reset link is printed
  to the container log. Identical response whether or not the email exists
- `GET /auth/reset-password/validate` (public) — check a reset token (30 min, single use)
- `POST /auth/reset-password` (public, 20/10min/IP) — complete the reset
- `GET /auth/me` (login) — current user
- `POST /auth/logout` (login) — keeps the token, returns `keptToken: true`
- Passwords are 6–128 characters. Changing a password does **not** require the old one

### Devices

- `GET /device` (login) — list your devices
- `POST /device` (login, 20/h) — add one; the full token is returned **once**
- `DELETE /device/:id` (login) — revoke
- `POST /device/rotate` (login, 20/h) — replace the token currently in use; the old value dies
  immediately
- `POST /device/:id/reveal` (login, 10/h **per user**) — see below

**`GET /device` response.** The master key row is the one exception: its plaintext is **not**
returned.

```json
[
  {
    "id": 1,
    "name": "默认 Token",
    "token": null,
    "tokenPreview": "kR9mX2pQ",
    "tokenHidden": true,
    "isCurrent": true,
    "isMaster": true,
    "lastSeen": 1789968398982,
    "createdAt": 1789968398982
  },
  {
    "id": 7,
    "name": "My phone",
    "token": "cz.xxxxxxxxxxxxxxxxxxxxxxxxxxxxxx",
    "tokenPreview": null,
    "tokenHidden": false,
    "isCurrent": false,
    "isMaster": false,
    "lastSeen": 1789968398982,
    "createdAt": 1789968398982
  }
]
```

| Field | Meaning |
|---|---|
| `token` | `null` for the master key row; full value otherwise |
| `tokenPreview` | 8-char fingerprint of the master key (same algorithm as the startup log: skip the `cz.` prefix, take 8 chars) — only for matching against other records |
| `tokenHidden` | when `true`, clients must route "copy" through `POST /device/:id/reveal` |
| `isMaster` | this row is the global master key; it cannot be deleted (the server rejects it) |

Why the master key is special: it is the **global super-admin credential**, and this row is
visible to anyone who obtains the super-admin's password. Once copied, **changing the password
does not invalidate it** — it keeps working until the master key itself is rotated. Being logged
in is not sufficient authorisation to read it.

**`POST /device/:id/reveal`** — fetch the master key in plaintext. Requires the current
account's password again.

```json
// request
{ "password": "current account password" }

// 200
{ "token": "cz.xxxxxxxxxxxxxxxxxxxxxxxxxxxxxx" }
```

| Case | Response |
|---|---|
| Correct password, row is the master key | `200` + full token; writes a `device.reveal` audit entry |
| Wrong password | `403` — **`403`, never `401`** (see the status code convention) |
| Missing `password` | `400` |
| Row is not the master key | `400 这一行不需要二次验证` |
| Row belongs to another user | `404` |

The password is only compared in memory; it is never logged and never stored in the audit `meta`.

### Self-service account edits

- `POST /user/avatar` / `DELETE /user/avatar` (login)
- `PATCH /user/profile` / `PATCH /user/email` / `PATCH /user/username` / `PATCH /user/password`
  (login)
- `GET /user/list` (super admin) — all users
- `PATCH /user/:id/role` (super admin) — promote/demote. You cannot change your own role, and at
  least one super admin must remain

## 3. Channels

- `GET /channel` (login) — channels **you are subscribed to** (super admin included)
- `GET /channel/discover` (login) — public channels only
- `GET /channel/:id` (login)
- `POST /channel` (login) — create; the creator is auto-subscribed
- `PATCH /channel/:id` / `DELETE /channel/:id` (creator / super admin)
- `POST /channel/:id/icon` (creator / super admin)
- `POST|DELETE|PATCH /channel/:id/subscribe` (login) — subscribe, unsubscribe, mute

> `is_public = false` hides a channel from **everyone**, super admin included.
> A password-protected channel returns `403 密码错误` on a wrong password.

## 4. Messages

- `GET /message` (login) — incremental pull using an **id watermark** (`since=`)
- `GET /message/deleted` (login) — tombstones. The watermark is `deleted_at` in
  **milliseconds** and uses a **composite cursor `(deleted_at, id)`**; a single cursor silently
  misses rows when a batch delete shares one timestamp
- `POST /message` (login) — post a message
- `DELETE /message/:id` (subscriber / admin) — soft delete
- `GET /message/search` (login)
- `POST /message/:id/read` / `unread` / `read-all` (login) — read state is per user
- `POST /message/:id/archive` / `unarchive` (login)
- `GET /message/unread-counts` (login)

⚠️ An id watermark only expresses "what is new", never "what disappeared" — deletions must be
reconciled through `GET /message/deleted`. Cascaded deletions that happen while a client is
offline are lost permanently.

## 5. Applications

- `GET /application` (login) — **only your own apps**; the app token is never returned in
  plaintext
- `POST /application` / `PATCH /application/:id` / `DELETE /application/:id` (login)
- `POST /application/:id/icon` (login)

## 6. Attachments

- `POST /attachment?name=xxx.png` (login, 10/min) — 8 MB per file, 500 MB total
- Orphaned files are reclaimed when a message is deleted. There is **no delete endpoint**; to
  clean up manually, remove the file inside the container

## 7. Webhook

- `POST /hook/:token` (public) — the **app** token goes in the path, never the master key
- Query parameters: `title`, `priority`, `channel_id`, `silent`, `tags`
- Processing pipeline: parse → template → route → aggregate → store → broadcast

⚠️ Validation failures are reported with `console.warn` and still return **HTTP 200** —
the response body says `{ "received": true }` before validation runs. Grep the log for
`call_webhook 已拒绝` when a push silently goes nowhere.

- `POST /hook/preview` (public, 30/min) — render a template without storing anything

### Aggregation

Messages are folded when channel + app + title are **exactly** equal. Two windows are both
required:

| Env var | Default | Measured from |
|---|---|---|
| `AGG_WINDOW_MS` | 300000 (5 min) | the previous fold |
| `AGG_MAX_LIFETIME_MS` | 1800000 (30 min) | the message's creation time |

Measuring only the first one keeps an old message alive indefinitely. A fold does not change
`id`, so an aggregated message **never floats back to the top**.

## 8. Routing rules

- `GET /route` / `POST /route` / `PATCH /route/:id` / `DELETE /route/:id` (login) — you only see
  your own rules
- `POST /route/test` (login) — dry run. Only a `{name}` context exists, so `channel_id` and
  `app_id` never match here
- `GET /route/templates` (login) — built-in templates

## 9. HTTPS certificate

- `GET /certs/status` / `POST /certs/fullchain` / `POST /certs/privkey` / `DELETE /certs`
  (admin) — upload a certificate to enable HTTPS/WSS; hot-reloaded

## 10. Background

- `GET /background` / `POST /background` / `DELETE /background` (login) — per-user background
  image

## 11. Audit log

- `GET /audit` (admin) — sign-in, sign-up, rule changes, deletions, `device.reveal`, …
- Retention: `AUDIT_RETENTION_DAYS` (default 90) and `AUDIT_MAX_ROWS` (default 50000)

## 12. WebSocket

- **Connect** — `ws://<host>:20010/stream` (only `/stream` is accepted; anything else is dropped
  during the upgrade)
- **Server push** — `message`, `messageAggregated`, `messageRead`, `messageArchived`,
  `channelCreated` / `channelUpdated` / `channelDeleted`, `subscriptionChanged`, `userUpdated`
- **Client send** — essentially a keep-alive
- **Delivery** — per channel: subscribers receive it, admins always receive it
- **Heartbeat** — the server pings; the client should answer

> ⚠️ `messageDeleted` is intentionally **not** in the client event whitelist — deletions are
> reconciled through `GET /message/deleted`, not the socket.
>
> ⚠️ `messageAggregated` is **not a new message**: it carries no `isRead` / `archivedAt`. Clients
> that upsert it over the whole row will wipe local read state — update content fields only.
>
> ⚠️ `silent` must travel with the socket event; a routing rule that only writes it to the
> database has no effect on clients that are already online.

## 13. Static assets

- Served from `public/` with **no authentication**. ⚠️ never leave `.bak` files there — they
  would be downloadable by anyone

## 14. Security headers

- CSP without `unsafe-inline` for scripts (hence the separate `boot.js`), plus the usual
  hardening headers. HSTS when `HSTS_MAX_AGE > 0` and the request is HTTPS

## 15. Super-admin page (site-wide, read-only)

- `GET /admin/channels` / `GET /admin/applications` / `GET /admin/routes` (super admin) — lists
  everything with owner attribution. This is the **only** place with site-wide visibility;
  ordinary fetches, pushes and unread counts always follow subscriptions, even for a super admin

## Message fields

- **Cover image priority** — `extras.image` → `client::display.url` →
  `client::notification.bigImageUrl`. Only the URL is stored, and it must be reachable from the
  phone. The **web UI** instead reads the first `<img>` in the message body
- **`extras.sender`** — sender snapshot, frozen at send time
- **`extras.app`** — app snapshot, frozen at send time
- Messages are **soft deleted** (`deleted_at`). `messages.id` is `AUTOINCREMENT` and never
  reused — that is what makes id-watermark sync safe
